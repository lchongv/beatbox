# Port de BeatBox a GTK4 — plan de implementación

> **Para los agentes:** este plan lo ejecuta un orquestador **Haiku** siguiendo
> `docs/gtk4/ORQUESTADOR.md`, que reparte las tareas entre trabajadores Haiku y
> Deepseek gratuito (OpenCode). Un trabajador lee `docs/gtk4/RECETAS.md` completo y
> **solo su tarea** de este archivo. El avance se lleva en `docs/gtk4/ESTADO.md`.

**Objetivo:** que BeatBox compile y funcione con GTK4 en la rama `gtk4`, con el mismo
aspecto y las mismas funciones que la 1.2 en GTK3.

**Arquitectura:** port «dirigido por el compilador». Se cambia la dependencia a GTK4 de
golpe y un andamio (`core/Gtk3Shim.vala`, tipos vacíos) hace que valac muestre todos los
errores del proyecto a la vez (~1.550, medidos); cada tarea es dueña de un grupo de
archivos sin solaparse con las demás y termina cuando `tools/gtk4-check.sh` da 0 errores
en ellos. Se conservan `TreeView`, `IconView`, los `CellRenderer`, `Gdk.Pixbuf` y los
diálogos clásicos (GTK4 los tiene); los menús contextuales pasan a un widget propio
(`PopMenu`) con la misma forma que `Gtk.Menu`, para que portarlos sea renombrar.

**Tecnología:** Vala 0.56, GTK ≥ 4.6, meson. Sin libadwaita.

**Material de apoyo (ya escrito y probado):**
- `docs/gtk4/RECETAS.md` — tabla GTK3 → GTK4 para este código, reglas del trabajador.
- `tools/gtk4-check.sh` — errores de valac de todo el código en ~2 s, filtrados por ruta.
- `tools/gtk4-deepseek.sh` — lanza un trabajador Deepseek para una tarea.
- `tools/gtk4-shot.sh` — arranca el programa en una pantalla virtual aislada, captura y avisos.
- `docs/gtk4/Gtk3Shim.vala` — el andamio (T00 lo copia a `core/`).
- `docs/gtk4/capturas/gtk3-referencia.png` — la ventana principal en GTK3, para comparar.

## Restricciones globales

- Rama `gtk4`, creada desde `master`. Nunca `git push`, nunca fusionar a `master`, nunca
  etiquetas ni releases, nunca `ninja install`: eso lo pide el usuario cuando revise.
- Directorio de compilación `build-gtk4` (el `build/` de GTK3 no se toca).
- Sin Docker ni descargas grandes (conexión medida). Nada de instalar paquetes.
- Solo API de GTK 4.6 (la AppImage se arma en Ubuntu 22.04). Ver regla 4 de RECETAS.
- No se convierte `TreeView` → `ColumnView` ni `IconView` → `GridView`. No se añade libadwaita.
- `src/Store/` es código muerto: no se porta.
- Los commits los hace solo el orquestador, con el autor ya configurado en el repo (no
  pasar `-c user.email`), mensaje en inglés que empieza con `GTK4: ` y la línea final
  `Co-Authored-By:` del modelo que hizo el trabajo.
- El usuario no quiere la palabra «iTunes» en nada visible para quien usa el programa.

## Riesgos a revisar (lo que el compilador no ve)

Cada línea tiene su comprobación en la tarea indicada.

1. **Widgets que debían empezar ocultos aparecen visibles** (GTK4 muestra todo al crear;
   se borraron `no_show_all`). → T40, lista de widgets con `visible = false`.
2. **Carátulas y logos a 16 px** (`Gtk.Image` ya no usa el tamaño del pixbuf). → T31:
   `grep` de `set_from_pixbuf|from_pixbuf` fuera de `UI.show_pixbuf` debe dar 0.
3. **Arrastrar varias canciones seleccionadas a una lista de la barra lateral** (la
   selección múltiple se pierde al pulsar). → T20, y revisión manual.
4. **CSS de las apariencias con selectores o propiedades que GTK4 ignora en silencio.** →
   T41 (errores del analizador) y revisión manual por apariencia.
5. **Funcionalidad borrada para que compile.** → puerta del orquestador (proporción de
   líneas borradas) y T42 (todos los `GTK4-PENDIENTE`).
